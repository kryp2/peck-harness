# Agent Note：agent-preset 暂存值至多等待两分钟

Status: implemented

[English](2026-08-18-agent-preset-stage-expires.md) | 中文

## 问题

新建会话 chip 会把一次 preset 选择**暂存**，直到某个会话成为当前会话且仍为空白（[creator 引入提示](../../archived/feature/2026-08-10-creator-guidance-introduce-cue.md)搭载同一个暂存值）。暂存值没有期限，而 seat 在**每一次**会话列表变更时都会尝试采用它。一个会话收到了五次已提交的 preset 切换，其中四次发生在 28 毫秒之内，每一次都覆盖了前一次；最后一次写入胜出，会话最终运行在一个用户从未确定的 preset 上。

这轮风暴是过期暂存值自我花费的结果。在没有会话存在的地方做出的选择会一直暂存，直到某个空白会话到来；一个从未完成的流程（被弃用的标签页、没有落地的启动）会让该暂存值无限期等待。每个标签页都会把每一次已提交的 preset 切换折进自己的会话列表，而折叠本身会改动列表——于是一个标签页的提交重新触发了其他所有标签页遗留的暂存值，全部射向同一个空白会话，每个被花费的暂存值又发出一次切换，覆盖了用户真正做出的选择。seat 还缺少忙碌守卫，因此选择调用在途时的列表变更可能铸造第二次调用，与第一次竞速。

## 决定

暂存值携带它被做出的时刻，`apply()` 丢弃超过两分钟的暂存值，让 chip 回落到部署默认值。该常量是暂存机制自身的属性，而非部署选择：两条暂存流程——chip 选择之后的工作区连接、分区入口之后的 creator 启动——都在片刻之内铸造它们的会话，因此窗口关闭后仍在等待的暂存值属于一个已经离开的流程。固定的协议常量让每个部署保持同一套语义；配置字段只会允许某个部署重新掀起风暴。

`apply()` 在一次选择在途时也会直接返回：在途调用已经携带了该选择，为它再发第二次调用只会与第一次竞速。

选择与时间戳存放在同一个私有字段里，二者不可能漂移；每条消费或丢弃该选择的路径都同时清空两者。

## 考虑过的替代方案

**在任何一次采用失败时消费暂存值。** 被拒绝：文档化的流程在其会话存在**之前**暂存——hero 界面的选择要等工作区连接随后产生的会话才抵达，而此刻无法服务对它来说是常态。

**把暂存值限定到它的目标会话。** 被拒绝：流程铸造的会话在暂存时刻尚不存在，而「暂存之后创建的会话」又会排除文档化的对既有空白会话的复用。

**把窗口做成 Config 字段。** 被拒绝：窗口没有任何随部署变化的成分；这里的可调参数只是一个重新启用该缺陷的旋钮。

**通过线缆协调各标签页。** 被拒绝：宿主本就按会话排队选择并逐一提交；缺陷在于过期的客户端意图，期限机制无需新的线缆字段即可将其移除。

## 后果

超过两分钟的暂存值不再能够自我花费：观察到的风暴不可能复现，过期的暂存值会让 chip 可见地回落到默认值，而不是继续静默等待。窗口之内，文档化的交接——暂存值抵达某个成为当前会话的空白会话——保持不变；遇已启动会话即丢弃、一经使用即消费的语义也原样保留。

一处残留出于设计：两个标签页在窗口内各自暂存不同选择时，仍可能对同一个空白会话竞速。宿主按会话串行化切换，最后一次提交胜出——这是多个标签页对一个会话的实时争用，不是过期意图；解决它属于会话级所有权的决定，不属于本修复。

两个真实组合用例钉住了行为：一次被延迟应答的选择，在列表变更于其下方运行时不会收到第二次调用；一个被假时钟推进到窗口之外的暂存值，会在空白会话最终到来时丢弃自身并恢复默认值。包 [README](../../../../packages/client/ui-agent-preset/README.zh.md) 在暂存描述旁写明了该窗口。
